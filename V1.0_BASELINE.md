# SO-DETR V1.0 — Clean Baseline

V1.0 is an engineering baseline. It does **not** change the published SO-DETR architecture, query selection, loss formulation, or knowledge-distillation method.

Its purpose is to make the original code usable as a controlled starting point for later ablations.

## What changed

- Added a portable command-line trainer: `train_sodetr_visdrone.py`.
- Removed the machine-specific absolute paths from `train_exp.py`.
- Added a VisDrone dataset YAML template.
- Added a baseline dependency list and `.gitignore`.
- Fixed `logical_loss_ratio: 0.1,` so the value is parsed as a float.
- Standardized the default research protocol used in this project.
- Fixed the vendored Ultralytics DDP relaunch so command-line arguments such as `--data` are forwarded to every `torchrun` worker.

## What did not change

- `SPDConv` and `DDF` implementation.
- P2/P3/P4 high-resolution fusion topology.
- Expanded/Inner-IoU behavior.
- RT-DETR decoder and query count.
- Original SO-DETR response distillation code.

This boundary is important: results from V1.0 are the reference measurements for structural changes introduced in V1.1 and later.

## Environment

The repository contains a vendored Ultralytics `8.0.201` implementation. Do not install a separate `ultralytics` package into the same environment.

Install PyTorch and torchvision for the CUDA version available on the server, then install the remaining dependencies:

```bash
pip install -r requirements_v1.txt
```

Run commands from the repository root so Python imports the local `ultralytics` package.

## Dataset

Copy the template and edit its absolute dataset root:

```bash
cp configs/visdrone-local.example.yaml configs/visdrone-local.yaml
```

## Main V1.0 baseline

The development baseline is SO-DETR-R18 without knowledge distillation:

```bash
python train_sodetr_visdrone.py \
  --model r18 \
  --data configs/visdrone-local.yaml \
  --device 0,1 \
  --epochs 400 \
  --patience 40 \
  --batch 8 \
  --imgsz 640 \
  --workers 8 \
  --seed 0 \
  --optimizer AdamW \
  --lr0 0.0001 \
  --lrf 1.0 \
  --weight-decay 0.0001 \
  --mixup 0.2 \
  --close-mosaic 0
```

Equivalent shorter command, because these are the V1.0 defaults:

```bash
python train_sodetr_visdrone.py \
  --model r18 \
  --data configs/visdrone-local.yaml
```

The default output directory is:

```text
runs/train/sodetr-v1-r18-baseline-seed0
```

## Multi-GPU DDP behavior

For `--device 0,1`, the local Ultralytics trainer relaunches the training entry point through `torch.distributed.run`. V1.0 forwards the original command-line arguments to the child workers, so required arguments such as `--data` are preserved.

The debug command should therefore end with the original training arguments, for example:

```text
... torch.distributed.run ... train_sodetr_visdrone.py --model r18 --data /path/to/VisDrone-local.yaml ...
```

The `OMP_NUM_THREADS=1` message and the `timm.models.layers` deprecation message are warnings, not training failures.

## Multi-seed verification

Only run additional seeds after seed 0 completes normally:

```bash
python train_sodetr_visdrone.py --model r18 --data configs/visdrone-local.yaml --seed 1
python train_sodetr_visdrone.py --model r18 --data configs/visdrone-local.yaml --seed 2
```

Record at least AP50-95, AP50, AP75, precision, recall, per-class AP, training time, peak memory, parameters, GFLOPs, and inference latency.

## Resume

```bash
python train_sodetr_visdrone.py \
  --data configs/visdrone-local.yaml \
  --resume runs/train/sodetr-v1-r18-baseline-seed0/weights/last.pt
```

The ordinary V1.0 trainer uses the standard Ultralytics resume path. The separate legacy distillation trainer still has its own resume limitations and is outside the V1.0 baseline scope.
